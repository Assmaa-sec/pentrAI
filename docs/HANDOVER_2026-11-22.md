# PentrAI handover — 2026-11-22

The assessment PDF redesign is implemented and verified locally. The three
supplied PDFs guided the cover, overview, and finding detail layouts. For the
assessment lifecycle and worker architecture, see the [November 17 handover](HANDOVER_2026-11-17.md).

## What changed

- A navy A4 cover shows the assessment ID, the saved report date, and the number
  of detected findings.
- The overview shows severity totals and a list of up to four findings, ordered
  by recorded severity. Detections without a severity are labeled
  **Unspecified**. The report retains its original scope, coverage, and
  validation wording, including for zero-finding assessments.
- Finding details use severity badges, readable SHA-256 evidence panels,
  consistent headers, and page numbers. Long text and evidence blocks flow
  across pages. Long titles are shortened in the overview as needed.

## How the export fits into the assessment workflow

`GET /v1/organizations/{organization_id}/scans/{scan_id}/report.pdf` checks
access to the organization and scan before reading the saved report. The PDF
branch also reads the scan's recorded findings in the `detected` state for the
overview. The report body comes from `ScanReport.markdown`, and the cover uses
the report's persisted creation date.

Rendering is a read-only download step after report persistence. An existing
assessment gets the new layout when its PDF is downloaded again. Markdown and
DOCX exports use their own branches of the download route.

| File | Role in this change |
| --- | --- |
| `control_plane/report_pdf.py` | Standard-library PDF renderer. Lays out static, runner-backed, and older reports. Escapes report text into PDF literals. |
| `control_plane/report_exports.py` | Re-exports `render_pdf` at its original import path and contains the DOCX exporter. |
| `control_plane/app.py` | Supplies the saved metadata and tenant-scoped detection summary only in the PDF download branch. |
| `tests/test_report_exports.py` | Exercises severity summaries, zero findings, escaped text, and evidence and code-block pagination. |
| `tests/test_control_plane_api.py` | Checks the PDF attachment response and a 404 for a download requested under a different organization. |

The PDF changes are in the working tree at this checkpoint. Include the new
renderer and its test file when transferring the patch.

## Known limitations and local examples

The PDF uses built-in Helvetica and Courier with WinAnsi encoding. Characters
outside that encoding display as `?`.

The local examples are `findings.pdf`, `source.pdf`, and `no-findings.pdf` in
`.tmp/assessment-pdf-render-review/`. They were generated from synthetic data and
are in the Git-ignored scratch directory.
